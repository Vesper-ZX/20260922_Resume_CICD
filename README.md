# 第 6 课教师答案

本课没有唯一代码填空答案，以本课课堂操作手册中的“测试、修复与最终发布”验收项和完整工程为准。

合格问题记录必须包含：重现步骤、实际现象、涉及文件、修复内容、同一步骤重测结果。

最终检查：资料、图片、链接、手机布局、导航状态、作品数组、Git 提交和 Pages 网址均正常。提交说明应写清修复原因与结果。

# 日常维护说明

纯静态站点，**没有构建步骤、没有 npm 依赖**。改完直接刷新浏览器就能看到效果。

## 文件分工

| 文件 | 角色 | 日常要不要改 |
| --- | --- | --- |
| `index.html` | **页面内容**（文字、图片、链接） | 要，90% 的改动都在这里 |
| `styles.css` | 外观（配色、排版、响应式、动效样式） | 一般不用 |
| `app.js` | 进度条 / 栏目徽标 / 导航高亮 / 返回顶部 | 不用 |
| `works-render.js` | 作品的标签筛选与年份排序 | 不用 |
| `motion.js` | 动效层（可整个删掉，功能不受影响） | 不用 |
| `works-data.js` | 作品数组（**镜像**，见下） | 改作品时要同步 |
| `tools/check-page.mjs` | 提交前的自检脚本 | 不用 |

`index.html` 里每个栏目上方都有一行注释说明「加一条内容怎么加」，文件末尾还有一个**栏目模板**，复制即可新增栏目。

## 常见操作

**加一条经历 / 项目 / 奖项**：找到对应栏目，整块复制里面标了「复制此行」的元素，改文字即可。

**加一个作品**：复制一个 `<li class="work-card">` 整块，改 5 处 —— `data-tags`（筛选标签）、`data-year`（年份）、`a href`（网址）、`img src/alt`（截图与说明）、`h3`+`p`（标题与一句话说明）。

**加一个栏目**：复制文件末尾的「栏目模板」，改 `id` 和标题，**并到 `<nav>` 里加一行链接**。导航里的 `href` 和栏目的 `id` 必须完全一致。

> ⚠️ `works-data.js` 是页面上那份作品列表的**镜像副本，不是数据源**。页面的筛选排序读的是 HTML 里的 `data-tags` / `data-year`。所以**改作品要同时改 `index.html` 和 `works-data.js`**，两边不一致时自检会报错（第 8 项），不会静默出错。

## 红线

这几条由 `tools/check-page.mjs` 强制检查，写错会挡住发布：

- 图片的 `alt` 不能为空，也不能只写「图片」这类笼统词
- `id` 不能重复
- 这 5 个 `id` 一个都不能删，删了 `app.js` 会报错、整页卡在半透明状态：
  `#reading-progress`、`#section-indicator`、`#to-top`、`#works-tags`、`#works-sort`
- 导航与栏目必须一一对应（有栏目没导航、有导航没栏目都算错）
- 不要写 `data-page-node-id` 这类编辑器残留属性

## 提交前自检

```bash
node tools/check-page.mjs
```

全绿（退出码 0）再提交。脚本共 8 项检查：文件是否齐全、编辑器残留属性、id 唯一性与必需 id、导航与栏目是否对齐、引用的本地文件是否存在、页内锚点、图片 alt、作品数组与页面是否一致。

## 发布

推送到 `main` 分支即自动发布到 GitHub Pages：

1. `.github/workflows/pages.yml` 先跑 `node tools/check-page.mjs`
2. 自检通过才打包整个目录发布；不通过则 `exit 1`，发布中止

也可以在 Actions 页面手动点 **Run workflow** 触发。
